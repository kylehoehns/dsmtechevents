# AGENTS.md

DSM Tech Events lists every public Des Moines tech meetup, user group and conference. The README covers how it works and how to add things; this file is the house rules and the traps.

## Shipping a change

- Every change is a branch and a pull request. `main` has a ruleset: no direct pushes, and a PR merges only once the `test-and-build` check is green. Wait for it, then `gh pr merge --merge --delete-branch`.
- Production deploys itself: Cloudflare Workers Builds deploys `main`, and every PR branch gets a preview at `<branch>-dsmtechevents.kyhoehns.workers.dev`. Deploy only through GitHub. The working dashboard settings are recorded in the comment at the top of `wrangler.jsonc`.
- `npm run build` runs the tests first, so a red test stops CI, Cloudflare and the data refresh alike.
- PR descriptions follow the owner's `pr` skill template (Summary, Evidence, Undo and Impact; 400 words max), written for a junior developer. Commit messages carry no trailers.

## Product rules

- **Pointer, not source of truth.** The site links to each group's own page; people RSVP there. Calendar exports, feeds, sign-up forms and per-event pages are out of scope.
- **Say it once.** Each fact appears once on screen: hide a repeated date, address, logo-as-photo, or a full name that only restates the short one. New UI follows the same rule.
- **This week stays above the fold** on a phone and a desktop.
- **Hands-off.** Prefer features that maintain themselves from data already fetched.
- **TAI means TechBrew only.** Its reader allow-lists TechBrew; other TAI events are members-only or invite-only.

## Data

- `data/cache/*.json` belongs to the refresh workflow (4×/day), which pushes it to `main` with a deploy key that bypasses the ruleset. After a local `npm run fetch`, discard the data changes (`git checkout data/cache data/archive`); commit a cache file only for a newly added group so it shows up before the next refresh.
- Cache files must stay byte-stable when nothing changed: `fetchedAt` only moves on real changes, and optional facts (`members`, `pastCount`) are omitted when unknown rather than written as `null`. Breaking this makes every refresh commit and deploy.
- `data/archive/<year>.json` is the long-term record of every ended event (the cache keeps only 90 days). The fetch maintains it (`scripts/archive.mjs`) and the refresh workflow commits it; like the cache, a file only changes when an event in it does.
- A failing source keeps its previous cache and opens one `source-broken` issue (`scripts/source-issues.mjs`); the other groups are unaffected. Readers in `scripts/sources/` throw on any unexpected page shape so that this alert fires instead of the group quietly emptying.
- New readers: `export default async (group, { get }) => events[]`, registered in `SOURCES` in `scripts/fetch-events.mjs`, with a trimmed fixture in `tests/fixtures/` and a test that proves the throw.
- Meetup group `urlname`s differ in case from our URLs; compare case-insensitively. From a Meetup events page, `enrich` takes only venue, address, photo, RSVPs and description; the feed stays the source for title, time and link.

## Time

Everything displays in Des Moines time (`site.timeZone`) wherever the viewer is. Convert local dates and times with `localToUtc` (`src/lib/time.mjs`); format and do day math with `src/lib/format.mjs`, which the build, `app.js` and the TV page all import. The Today / Tonight / Tomorrow / Happening now tag is `whenLabel()` and the poster stamp is `countdown()`: the build prints them and the browser re-checks them, so both must call those functions rather than re-deriving the rules. An event's last day is `lastDay()` (an event ending at midnight ends the day before).

## Front-end traps

- `.photo` is hidden by a global rule (the phone layout); a new image needs its own class.
- Hover styles live in the single `@media (hover: hover)` block at the end of `global.css`; phones otherwise keep `:hover` stuck on the last thing tapped.
- Anything embedded in a `<script>` with `set:html` goes through `toScript()` (`src/lib/jsonld.mjs`), which escapes `<`; event titles come from Meetup.
- Astro drops the line break between text and a tag on another source line (`the\n<a>` renders as `the<a>`, `</a>\nfull` as `</a>full`); keep a link on the same line as the words on both sides. `scripts/check-dist.mjs` fails the build when it happens.
- `Layout.astro` with `bare` renders only the page (the `/tv/` lobby screen): no masthead, footer, or their scripts.
- Colors are tokens on `:root` in `global.css`, redefined for dark mode; style through the tokens so both themes stay readable.
- The share image and the icons are generated by `npm run og` and `npm run icons` and committed; edit the scripts, rerun, commit the output.

## Verifying UI work

Build, then check the result in a real browser at 1280 and 390 wide, in light and dark. For date-dependent views (headliners, Today/Tonight labels, the TV page), build with a faked clock and set the browser's clock to match: `scripts/fake-now.mjs` shows how, with Playwright's `page.clock.install`.
